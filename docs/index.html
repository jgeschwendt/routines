routines · design

executable markdown on rails

A routine is a single markdown document — frontmatter for schedule, prose for judgment, fenced sh blocks for mechanics. routine runs the blocks deterministically; when one fails, the document itself becomes the prompt: claude receives the error in full context, repairs state, and the runner retries the block once. Every scheduler — launchd locally, a CI cron, a human at a shell — is a dumb tick that ends at the same routine run.

Layout — a routines home, and the tool

The documents live in a routines home — $ROUTINE_HOME, default ~/.routines — and this repo is only the tool: personal routines never enter it.

  • ROUTINE_HOME is the only anchor — ROUTINE_DIR (documents) and ROUTINE_STATE (run state) derive from it and are overridable individually; setup pins all three into the launchd agent, so re-run it after moving any.
  • Test seams — ROUTINE_CLAUDE, ROUTINE_NOW and ROUTINE_PMSET redirect claude, the clock and the dark-wake probe; launchd is reached as hotswap reaches it, launchctl on PATH under $HOME/Library/LaunchAgents, so the suite stubs it there and names its scratch HOME in HOTSWAP_TEST_HOME; with no launchctl on PATH (Linux, the CI tick's host) setup writes no agent.

The document — $ROUTINE_HOME/<name>.md

One file per routine. Frontmatter is flat key: value, no YAML library: # starts a comment, one pair of surrounding quotes is stripped, CRLF, trailing blanks and a leading BOM are tolerated. Only sh / bash fences execute, sequentially, each under bash -e; other fences are material for the prose. Fences follow CommonMark (``` or ~~~, 3+ long, indent 0–3 stripped, closed only by the same character at least as long); a fence inside an HTML comment is disabled. A block that needs an asset writes or references sibling paths.

try / catch — the failure contract

The happy path never calls a model. The document is the handler's context precisely because it was written before anything broke.

① try
  • blocks run in order; each block's output is appended to the run log under a block delimiter
  • each block's exit code is the truth — nothing interprets it
② catch — on_error: claude
  • the runner invokes claude --model opus --permission-mode=auto --no-session-persistence -p with the prompt on stdin (never argv — a large document passes ARG_MAX): the full document, the failing block, and its captured output, each section between markers carrying the run's random suffix so output cannot forge its end, cwd = the routines home, env carrying ROUTINE_NAME, ROUTINE_STATE_DIR and ROUTINE_HOME as the blocks see them
  • instruction: running unattended; diagnose and repair state; do not continue the routine yourself
③ retry
  • the runner re-executes the failing block once — pass ⇒ continue to the next block; fail ⇒ the routine exits with that block's code
  • one repair attempt per block, no loops
④ degrade
  • no claude binary, or no credentials (claude auth status exits 1 — bare CI) ⇒ behaves as on_error: fail, with the reason logged; credentials are never verified, so a bad or expired one still runs the catch, and its failed agent stamps the degraded marker that a repair which ran clears
  • The agent never steers control flow — the deterministic retry is the verdict, never the agent's exit code.

Due-ness — derived, never matched

A routine is due when next-fire-after(last started run, schedule) ≤ now; a missing last-run.json, or one stamped ahead of the clock (a stepped clock), means due. Cron evaluates in UTC — one clock for launchd, CI, and the shell.

one evaluator buyswhy
CI correctness under delayed or skipped tickscompare against the last run, not "does now match the expr"
launchd catch-up after sleepfree — the same comparison, no wake hook
routine run --due as the universal entryevery scheduler is a dumb tick

next-fire-after walks days forward from the last run, dates by arithmetic, never a fork (horizon eight years, so Feb 29 recurs; dead months skip to their 28th) — dumb, correct, sub-second. Day-of-month and day-of-week follow cronie: OR when both are restricted, AND when either opens with * (*/2 included).

Schedulers are dumb ticks

Neither scheduler knows a routine's schedule. Both wake up, ask the one evaluator what is due, and exit.

launchd — dev.gigantic.routines.due
  • routine setup writes it, first booting out the retired com.routines.due; --remove boots it out; the upgrade agent is hotswap's alone
  • StartInterval 60 + RunAtLoad true, running ~/.local/bin/routine run --due, the link through hotswap's current — a swap needs no rewrite, and a loaded tick whose plist changed is booted out and bootstrapped again — with PATH and the ROUTINE_HOME/ROUTINE_DIR/ROUTINE_STATE anchors stamped (XML-escaped) — no cd, the runner enters the routines home itself
  • RunAtLoad fires once at load — bootstrap and login; after a sleep the first StartInterval fire (those due while asleep are missed, launchd.plist(5)) runs --due, and derived due-ness catches up whatever fell due
CI — one static workflow
  • routine sync-ci emits .github/workflows/routines.yaml into the repo it is invoked in
  • cron every 15 min + workflow_dispatch, one tick at a time (a concurrency group: runners share no lock); ROUTINE_HOME = that repo's routines/; restore routines/.state from actions/cache; mise-action with no tools, then mise x packslip:jgeschwendt/routines@latest -- env -u GITHUB_TOKEN routine run --due — mise verifies the release against its signed packslip, MISE_MINIMUM_RELEASE_AGE_EXCLUDES=packslip:jgeschwendt/routines lets it see one under 24 h old, and env -u drops the token mise-action exports; save the cache
  • the save runs under if: always() — actions/cache saves only on success, so one red routine would roll back every other routine's state
  • each tick saves a new key, keyed by run and attempt so a re-run never collides with a taken one; once this run's key is listed (a failed save still exits 0) every older routines-state- entry on the same ref is deleted (gh cache delete, actions: write)
  • every action is pinned by commit and checkout persists no token (persist-credentials: false): a moved tag cannot run under the job's token, and no block reads it from .git/config — a block that needs git auth brings its own
  • cache eviction makes everything due once — idempotency absorbs it
  • the private ~/.routines repo carries no workflow: its only tick is launchd's

One execution path, end to end: the tick, the gate, the lock, the blocks, and the single catch that repairs and retries.

Verbs

The whole surface, plus help and --version.

verbduty
run <name>run one document through the wrapper — gate, lock, timeout, try/catch
run --duethe universal entry — each due routine a routine run <name> child ignoring INT and QUIT, all started at once and waited for; silent when none are; exits 1 when any failed
statusfrontmatter × last-run join: schedule, due? (bad for a schedule the parser rejects, which never fires), last exit, duration
health [--json]one verdict over the home, from the runner's own parsers and state, never a second reading of them. Per routine the first match wins: lint — every reason the runner would refuse or mis-read the doc (no sh/bash block, an on_error neither claude nor fail, a timeout that is no positive number, a schedule that never fires); wedged — a live lock held past the doc's timeout and the watchdog's minute; failed, or acknowledged while an ack holds that exit; stale — due, idle, and passed over by a sweep that could dispatch (a tick docs= line in tick.log no defer dark-wake follows) half an hour after it fell due, so a slept machine or a dark wake never reads as stale. The tick is not-loaded, stale when tick.log has been quiet ten minutes since its last line or the machine's last wake (sysctl -n kern.waketime), whichever is later, and no routine runs (a long run holds the tick), or unmanaged with no launchctl; a slug-less doc opening with frontmatter and state with no doc are red too (archive the state, never delete it). Plain prints each red finding with its fix and a closing verdict; --json prints one line for an app to render, every finding — a routine's, the tick's, a skipped doc's, an orphan's — carrying the fix the plain report prints, so a renderer never invents one. The watcher belongs outside the tick: an app that calls routine health sees a dead tick, a routine riding the tick cannot
ack <name> [reason…] | --clearhold the last run's failed exit as known in .state/<name>/ack, so health reports it acknowledged and stays green; the runner drops the ack when a run exits otherwise — green, or a different failure — so an ack never hides a new kind of failure; --clear drops it by hand
setup [--remove]aliases install · uninstall; hotswap::ensure first — the latest release installed when none is, ~/.local/bin/routine linked through current, the upgrade agent dev.gigantic.routines.upgrade written, loaded or reloaded by hotswap alone — then write and load the tick on that link, reloading it when its plist changed. The tick never runs the binary that ran setup, so a checkout's cargo run -- setup wires the installed release, its own plist rendered until the next swap reruns the release's setup. --remove boots the tick out, deletes it and the link, and hotswap::forget drops the upgrade agent, the layout and the record
upgrade [--check | --back | --retry]hotswap::upgrade: packslip installs the release, hotswap repoints current; the drain refuses while any routine holds its lock/ (setup's reload and the tick's kickstart would kill it), then routine setup, a kickstart of the tick, and routine status as the smoke probe, 120 s a step — green settles, red rolls back. Exits 0 green or settled, 1 red or refused, 2 unable to try. Off mise: the release before this one bumps mise, then drains; a refused drain strands the host on the new binary through mise's shim, and the next tick's upgrade, run through that shim, lays out every version mise holds, makes the running one current and moves the upgrade agent onto the link before its own drain; its setup moves the tick at the swap. A red first swap rolls back onto mise's copy of the old release with mise use -g packslip:jgeschwendt/routines@<V> first, so its setup's shim runs it; the next release moves the host again. mise's dirs are left alone; once no version on disk predates hotswap, an upgrade says to run mise unuse -g packslip:jgeschwendt/routines

1run --due: a dispatched routine failed · health: anything is red · install/setup: the release cannot install or link, a plist cannot land, or launchctl bootstrap failed · upgrade: red, or refused by the drain or the red hold
elsethe failing block's own code, passed through
  • Blocks are idempotent — catch-retry, cache eviction, and tick overlap can all double-fire; the lock serializes, idempotency absorbs.
  • One binary, no runtime dependencies — std plus the hotswap crate, src/sys.rs the only unsafe module (sigaction → a pipe, write, kill, under #![expect(unsafe_code)]); claude is needed only when a catch fires or a block calls it.
  • $ROUTINE_HOME/.state/ is never committed — CI persists routines/.state through actions/cache only.

Scale: the runner is ~1,900 lines of Rust outside its tests (measured 2026-11-22 · non-blank lines of src/*.rs above each #[cfg(test)]).

  2. An old reap guard is passed, not claimed — two runs meeting a crashed reaper's lock.reap can both reap — reproduced by injection (s-20261027T0645Z); claiming it by rename is still ABA-prone, so it needs guard identity (pid + start).
  3. hk 2.5.0 → 2.8.1 (mise.toml, hk.pkl): no breaking change listed; the shift sandbox cannot install it.

Rejected alternatives

  • routine.conf + run.sh per routine dir (the first sketch) — superseded by the executable-markdown directive: the document unifies script and prompt; two files with implicit coupling become one artifact.
  • cron → StartCalendarInterval per-routine plists — punctual and power-optimal, but the translator (ranges/steps expanding into dict arrays) is the largest complexity sink in the system, drifts as a second schedule dialect, and still needs a separate catch-up mechanism. A 60-second tick that reads two files and exits is negligible.
  • A routine-core library crate — no second consumer; bifrost reads .state as a file format.
  • An async supervisor — a 60 s tick and a handful of children need no runtime.
  • "does now match the expr" due-check — breaks under delayed Actions ticks and machine sleep; derived due-ness handles both with the same code.
