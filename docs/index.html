routines · design

executable markdown on rails

A routine is a single markdown document — frontmatter for schedule, prose for judgment, fenced sh blocks for mechanics. bin/routine runs the blocks deterministically; when one fails, the document itself becomes the prompt: claude receives the error in full context, repairs state, and the runner retries the block once. Every scheduler — launchd locally, a CI cron, a human at a shell — is a dumb tick that ends at the same routine run.

Layout — a routines home, and the tool

The documents live in a routines home — $ROUTINE_HOME, default ~/.routines — and this repo is only the tool.

  • ROUTINE_HOME is the only anchor — ROUTINE_DIR (documents) and ROUTINE_STATE (run state) derive from it and are overridable individually; install pins all three into the launchd agent, so re-run it after moving any.
  • Test seams — ROUTINE_AGENTS_DIR, ROUTINE_LAUNCHCTL, ROUTINE_CLAUDE, ROUTINE_NOW, and ROUTINE_PMSET redirect launchd, claude, the clock, and the dark-wake probe — the seams the test suite runs through.

The document — $ROUTINE_HOME/<name>.md

Documents and run state live in a routines home — $ROUTINE_HOME, default ~/.routines, with state under its .state/; this repo is only the tool, so personal routines never enter it and the runner can move without breaking launchd. One file per routine. Frontmatter is flat key: value, parsed with awk — no yq, no yaml library; one pair of surrounding quotes is stripped; CRLF, trailing blanks and a leading BOM tolerated. Only sh / bash fences execute, sequentially, each under bash -e; other fences are material for the prose. Fences follow CommonMark (``` or ~~~, 3+ long, indent 0–3 stripped, closed only by the same character at least as long); a fence inside an HTML comment is disabled. A block that needs an asset writes or references sibling paths.

try / catch — the failure contract

The happy path never calls a model. The document is the handler's context precisely because it was written before anything broke.

① try
  • blocks run in order; each block's output is appended to the run log under a block delimiter
  • each block's exit code is the truth — nothing interprets it
② catch — on_error: claude
  • the runner invokes claude --model opus --permission-mode=auto --no-session-persistence -p with the prompt on stdin (never argv — a large document passes ARG_MAX): the full document, the failing block, and its captured output, each section between markers carrying the run's random suffix so output cannot forge its end, cwd = the routines home, env carrying ROUTINE_NAME, ROUTINE_STATE_DIR and ROUTINE_HOME as the blocks see them
  • instruction: running unattended; diagnose and repair state; do not continue the routine yourself
  • never start a final-message line with needs input: or failed: — the Stop hook would open an unkeyed thread per run — but use the stable thread key the document names
③ retry
  • the runner re-executes the failing block once — pass ⇒ continue to the next block; fail ⇒ the routine exits with that block's code
  • one repair attempt per block, no loops
④ degrade
  • no claude binary, or no credentials (claude auth status exits 1 — bare CI) ⇒ behaves as on_error: fail, with the reason logged; credentials are never verified, so a bad or expired one still runs the catch, and its failed agent stamps the degraded marker that a repair which ran clears
  • The agent never steers control flow — the deterministic retry is the verdict, never the agent's exit code.

Due-ness — derived, never matched

A routine is due when next-fire-after(last started run, schedule) ≤ now; a missing last-run.json, or one stamped ahead of the clock (a stepped clock), means due. Cron evaluates in UTC — one clock for launchd, CI, and the shell.

one evaluator buyswhy
CI correctness under delayed or skipped tickscompare against the last run, not "does now match the expr"
launchd catch-up after sleepfree — the same comparison, no wake hook
routine run --due as the universal entryevery scheduler is a dumb tick

next-fire-after walks days forward from the last run, dates by arithmetic, never a fork (horizon eight years, so Feb 29 recurs; dead months skip to their 28th) — dumb, correct, sub-second. Day-of-month and day-of-week follow cronie: OR when both are restricted, AND when either opens with * (*/2 included).

Schedulers are dumb ticks

Neither scheduler knows a routine's schedule. Both wake up, ask the one evaluator what is due, and exit.

launchd — dev.gigantic.routines.due
  • routine install renders one agent; routine uninstall boots it out; install retires the pre-2026-10-20 com.routines.due agent first
  • StartInterval 60 + RunAtLoad true, running /bin/bash -lc "exec <runner> run --due" with PATH and the ROUTINE_HOME/ROUTINE_DIR/ROUTINE_STATE anchors stamped (XML-escaped) — no cd, the runner enters the routines home itself
  • RunAtLoad fires once at load — bootstrap and login; after a sleep the first StartInterval fire (those due while asleep are missed, launchd.plist(5)) runs --due, and derived due-ness catches up whatever fell due
CI — one static workflow
  • routine sync-ci emits .github/workflows/routines.yaml into the repo it is invoked in
  • cron every 15 min + workflow_dispatch, one tick at a time (a concurrency group: runners share no lock); ROUTINE_HOME = that repo's routines/ dir, restore routines/.state from actions/cache, fetch bin/routine if absent, run --due, save cache
  • the save runs under if: always() — actions/cache saves only on success, so one red routine would roll back every other routine's state
  • each tick saves a new key, so once this run's key is listed (a failed save still exits 0) every older routines-state- entry on the same ref is deleted (gh cache delete, actions: write)
  • every action is pinned by commit and checkout persists no token (persist-credentials: false): a moved tag cannot run under the job's token, and no block reads it from .git/config — a block that needs git auth brings its own
  • cache eviction just makes everything due once — the idempotency contract absorbs it

The figure

One execution path, end to end: the tick, the gate, the lock, the blocks, and the single catch that repairs and retries.

Verbs

Six verbs — the whole surface. Every one of them ends at the same runner.

verbduty
run <name>run one document through the wrapper — gate, lock, timeout, try/catch
run --duethe universal entry — run every due routine at once and wait for all; silent when none are. Parallel dispatch unblocks routines within one sweep, but the tick lasts as long as its slowest routine and launchd fires no new tick meanwhile, so a long run holds every later sweep; exits 1 when any routine failed
statusfrontmatter × last-run join: schedule, due? (bad for a schedule the parser rejects, which never fires), last exit, duration
installrender and load the single launchd tick agent
uninstallboot the agent out and remove its plist
sync-ci(re)write ./.github/workflows/routines.yaml in the invoking repo

  • Blocks are idempotent — catch-retry, cache eviction, and tick overlap can all double-fire; the lock serializes, idempotency absorbs.
  • bash 3.2-safe, zero-dep — bin/routine is one script with no jq, yq, or GNU timeout; claude is needed only when a catch fires or a block calls it.
  • $ROUTINE_HOME/.state/ is never committed — CI persists routines/.state through actions/cache only.

Scale: the runner is ~770 lines of bash plus two small generators (plist, workflow).

Migration — a follow-on, not this build

Existing ad-hoc routines port one per document: a scheduled shell command inlines as a single block; an unattended-claude prompt becomes the document's prose plus a claude block, with git tracking its drift once it lives in the repo. A prose procedure paired with a mechanics script is already this shape — the standing proof of the format.

Next

  1. One long run holds every tick — run --due waits for its slowest; proposal tick-no-wait awaits the owner.
  2. An old reap guard is passed, not claimed — two runs meeting a crashed reaper's lock.reap can both reap; needs a SIGKILL mid-reap first.
  3. The CI workflow fetches bin/routine from main unpinned: pin a tag, once the owner cuts a release.
  4. hk 2.5.0 → 2.8.1 (mise.toml, hk.pkl): no breaking change listed; the shift sandbox cannot install it.

Rejected alternatives

  • routine.conf + run.sh per routine dir (the first sketch) — superseded by the executable-markdown directive: the document unifies script and prompt; two files with implicit coupling become one artifact.
  • cron → StartCalendarInterval per-routine plists — punctual and power-optimal, but the translator (ranges/steps expanding into dict arrays) is the largest complexity sink in the system, drifts as a second schedule dialect, and still needs a separate catch-up mechanism. A 60-second tick that reads two files and exits is negligible.
  • "does now match the expr" due-check — breaks under delayed Actions ticks and machine sleep; derived due-ness handles both with the same code.
