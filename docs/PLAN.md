# routines · design

Executable markdown on rails. A routine is a single markdown document — frontmatter for schedule, prose for judgment, fenced `sh` blocks for mechanics. `bin/routine` runs the blocks deterministically; when one fails, the document itself becomes the prompt: claude receives the error in full context, repairs state, and the runner retries the block once. Every scheduler — launchd locally, a CI cron, a human at a shell — is a dumb tick that ends at the same `routine run`.

```
try   { blocks, in order }          # zero-LLM happy path — cheap, fast, CI-safe
catch { claude("handle $error") }   # the doc's prose is the handler's context
```

## Layout

The documents live in a **routines home** — `$ROUTINE_HOME`, default `~/.routines` — and this repo is only the tool:

```
~/.routines/<name>.md            # the routine: frontmatter + prose + ```sh blocks
~/.routines/.state/<name>/       # lock/, last-run.json, runs.jsonl, logs/<ts>-<pid>.log
~/.routines/.state/tick.log      # the sweep's journal — one line per tick

bin/routine                      # the only runner — bash 3.2-safe, zero-dep
routines/                        # this repo's own routines — the CI convention
.github/workflows/routines.yml   # generated by `routine sync-ci`
docs/                            # this design + plate
```

Personal routines never enter the public tool repo, and the repo can move — or be replaced by a `curl`'d copy of `bin/routine` — without breaking launchd, because the agent points at the runner, not at a checkout.

`ROUTINE_HOME` is the only anchor: `ROUTINE_DIR` (documents) and `ROUTINE_STATE` (run state) derive from it and are overridable individually. `ROUTINE_AGENTS_DIR`, `ROUTINE_LAUNCHCTL`, `ROUTINE_CLAUDE`, and `ROUTINE_NOW` redirect launchd, claude, and the clock — the seams the test suite runs through.

## The routine document

```markdown
---
schedule: 30 7 * * 1-5
timeout: 600
requires: GITHUB_TOKEN
on_error: claude          # claude (default) | fail
---

# Morning brief

Prose is not decoration — it is the context the error-handler inherits:
intent, traps, judgment calls. Write it for the agent that arrives when
a block below has just failed.

​```sh
gh api notifications --paginate > .state/morning-brief/inbox.json
​```

​```sh
claude -p "summarize inbox.json …"   # a block may itself call claude — an agent step on rails
​```
```

- Frontmatter is flat `key: value`, parsed with sed — no yq, no yaml library.
- Only `sh` / `bash` fences execute, sequentially, each under `bash -e`; other fences are material for the prose.
- One file per routine; a block that needs an asset writes or references sibling paths.

## try / catch — the failure contract

- **try** — blocks run in order; each block's output is appended to the run log under a block delimiter; each block's exit code is the truth.
- **catch** (`on_error: claude`) — the runner invokes `claude --model opus --permission-mode=auto --no-session-persistence -p` with the full document, the failing block, and its captured output, cwd = the routines home. Instruction: running unattended; diagnose and repair state; do not continue the routine yourself.
- **retry** — the runner re-executes the failing block once. Pass ⇒ continue to the next block; fail ⇒ the routine exits with that block's code. One repair attempt per block, no loops.
- **degrade** — no claude binary or auth (bare CI) ⇒ behaves as `on_error: fail`, with the reason logged.

The agent never steers control flow — the deterministic retry is the verdict, not the agent's exit code.

## Due-ness: derived, never matched

A routine is due when `next-fire-after(last started run, schedule) ≤ now`; a missing `last-run.json` means due. Cron evaluates in UTC — one clock for launchd, CI, and the shell. One evaluator buys three things:

- CI correctness under delayed or skipped Actions ticks — compare against the last run, not "does now match the expr".
- launchd catch-up after sleep, for free.
- `routine run --due` as the universal entry — every scheduler is a dumb tick.

`next-fire-after` is a minute-scan forward from the last run (horizon 366 days) — dumb, correct, sub-second.

## Schedulers are dumb ticks

- **launchd** — `routine install` renders one agent, `com.routines.due`: `StartInterval` 60 + `RunAtLoad` true, running `/bin/bash -lc "exec <runner> run --due"` — no `cd`, since the runner cds into the routines home itself. RunAtLoad doubles as login/wake catch-up. `routine uninstall` boots it out.
- **CI** — `routine sync-ci` writes one static workflow into the repo it is invoked in: cron every 15 min + `workflow_dispatch`, `ROUTINE_HOME` = that repo's `routines/` dir (the CI convention — a repo's routines live beside its code), restore `routines/.state` from actions/cache, fetch `bin/routine` if the repo does not carry one, `bin/routine run --due`, save cache. Cache eviction just makes everything due once; the idempotency contract absorbs it.

## `routine run` — the shared wrapper

frontmatter → `requires` gate (exit 78, loud list of missing vars) → lock (`mkdir .state/<name>/lock`, pid inside; live pid ⇒ exit 75, dead pid ⇒ reap) → bash-native watchdog timeout (SIGTERM, SIGKILL after grace; exit 124) → `cd $ROUTINE_HOME` (blocks and the catch both run there; a missing home is exit 64) → blocks under the try/catch contract → `last-run.json` `{started, started_epoch, finished, exit, duration, degraded}` written on every path (trap) and appended to `runs.jsonl` → the failing block's exit passes through.

## Verbs

```
routine install | uninstall     # the single launchd tick agent
routine run <name> | --due
routine status                  # frontmatter × last-run join: schedule, due?, last exit, duration
routine sync-ci                 # (re)write ./.github/workflows/routines.yml in the invoking repo
```

## Exit codes

64 unknown routine / usage · 75 lock held · 78 requires missing · 124 timeout · otherwise the failing block's code.

## Contracts

- Blocks are idempotent — catch-retry, cache eviction, and tick overlap can all double-fire; the lock serializes, idempotency absorbs.
- `bin/routine` is bash 3.2-safe (macOS `/bin/bash` is frozen at 3.2.57) with zero external dependencies — no jq, yq, or GNU timeout. claude is needed only when a catch fires or a block calls it.
- `$ROUTINE_HOME/.state/` is never committed; CI persists `routines/.state` via actions/cache only.

Scale: the runner is ~200 lines of bash plus two small generators (plist, workflow).

## Migration (follow-on, not this build)

Existing ad-hoc routines port one per document: a scheduled shell command inlines as a single block; an unattended-claude prompt becomes the document's prose plus a claude block, with git tracking its drift once it lives in the repo. A prose procedure paired with a mechanics script is already this shape — the standing proof of the format.

## Rejected alternatives

- **`routine.conf` + `run.sh` per routine dir** (the first sketch) — superseded by the executable-markdown directive: the document unifies script and prompt; two files with implicit coupling become one artifact.
- **cron → StartCalendarInterval per-routine plists** — punctual and power-optimal, but the translator (ranges/steps expanding into dict arrays) is the largest complexity sink in the system, drifts as a second schedule dialect, and still needs a separate catch-up mechanism. A 60-second tick that reads two files and exits is negligible.
- **"does now match the expr" due-check** — breaks under delayed Actions ticks and machine sleep; derived due-ness handles both with the same code.
